# Role shapes

Choose one primary shape from the JD. These are defaults, not content quotas. Omit a section when verified evidence does not justify it.

## Backend / general SDE-2

Order:

1. Experience: four bullets
2. Open Source: one or two compact contributions when relevant and verified
3. Projects: Heimdall plus SimpleMQ by default; substitute only for a direct JD match
4. Skills: languages, backend/data, cloud/tooling
5. Education

Prioritize production Java/Spring ownership, latency, authorization, request orchestration, deployment/incident evidence, then distributed-systems projects. Do not use an objective by default.

## Full-stack SDE-2

Order:

1. Experience: four bullets, including one verified frontend/performance outcome
2. Projects: at most two; include a shipped UI only when the JD values frontend depth
3. Skills: frontend, backend, cloud/data
4. Education

Do not hide backend production evidence behind a project portfolio. Do not restore QA-only bullets simply because the JD mentions testing.

## AI infrastructure

Order:

1. Experience: three bullets; label the multi-agent work as a PoC unless the master confirms production use
2. Projects: Helios plus one systems project
3. Open Source or Writing: choose one based on the JD
4. Skills
5. Education

Treat professional inference/model-serving requirements as project-only evidence unless confirmed otherwise. Omit unverified throughput, TTFT, fragmentation, model, and hardware claims.

## Applied AI

Order:

1. Experience: the confirmed PoC plus two production software bullets
2. Projects: at most two directly relevant AI/tooling projects
3. Open Source or Writing when it proves the requested ecosystem
4. Skills
5. Education

Do not call a PoC production, user-facing, autonomous, or impactful without confirmed evidence. Do not list every agent framework in the skills bank.

## SRE / platform / DevOps

Order:

1. Experience: deployment pipeline, incident/RCA, reliability-related backend work
2. Projects: Heimdall and systemsfailed.dev when current facts are confirmed
3. Skills
4. Education

Do not claim Terraform, Prometheus, SLO ownership, on-call leadership, or production Go from adjacent evidence.

## HFT / low-latency

Default to `RED` or strong `AMBER` unless the JD is explicitly early-career. Professional Java work and educational C/C++ projects do not equal production low-latency trading experience.

If the user deliberately proceeds, lead with verified C/C++/Rust evidence, omit unverified competitive-programming and benchmark claims, and make the experience mismatch explicit in the rationale.

## Section choices

- Summary: omit by default; add only to explain a real transition.
- Objective: omit.
- Open Source: prefer for backend/platform roles when merged work is verified.
- Writing: use only when the JD values public technical communication or domain depth.
- Projects: two maximum for experienced-role applications.
- Internships: include only when directly relevant and stronger than the weakest project or public-work entry.
